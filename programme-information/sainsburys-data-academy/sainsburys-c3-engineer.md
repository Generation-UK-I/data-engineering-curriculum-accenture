# C3 - Basic

## Solution Design

**Applying Design Principles**: Begins to work independently on delegated aspects of an overall low complexity system design as part of a larger piece of work.

**Reusability**: Begins to understand and explain code reuse and the benefits it brings.

**Aligning with business objectives**: Understands the desired business outcomes that influence solution designs.

**Technical Innovations**: Begins suggesting new technologies, developing an increasing appreciation of the impact they will have while requiring assistance from more experienced colleagues.

## Solution Implementation

**Solution delivery**: Solves problems of low-medium complexity, by articulating implementable steps and delivering quality code.

**Coding standards**: Contributes towards code reviews of low-moderate complexity with support of other more experienced team members.

## Testing

**Foundation and Plan**: Writes unit tests at a level appropriate for the code they are writing.

**Scope**: Can specifically define the differences between unit, integration and component testing. Understands that component testing should target inputs and outputs, and what constitutes each.

**Functional vs. Performance**: Can define and contribute to non functional tests appropriate for the level of code they are writing.

**Approach**: Parameter based testing?

**Prioritisation**: Prioritise defects against issues/stories/features with guidance from more experienced team members.

## Security

**Awareness**: Begins to build simple security into aspects of the work they do under guidance  of more senior members.

**Speaking up**: Escalates when they see perceived security issues.

**Compliance**: Shows some understanding of how we manage personal information, and why it's important.

**Infrastructure**: Can explain the concepts of security in relation to infrastructure elements of a solution.

**Independence
Suggests solutions to identified  security issues and implements them subject to agreement and guidance from colleagues.

## Monitoring, Alerting & Healing

**Monitoring and Alerting**: Understands how to differentiate technical metrics which reflect application or system health, and business metrics.

**Visualisation**: Build dashboards for team use and defines key success metrics, with the support of more experienced team members.

**Operational support**: Suggests solutions to identified operational issues and implements them subject to agreement and guidance from colleagues.

## Dev Ops

**CI/CD**: Able to make changes to an existing CI pipeline under supervision to correct problems / update individual components to the latest versions. Is also to understand console output from a pipeline in order to assist in the diagnosis of a failure.

**Containerisation**: Can explain why you would use container orchestration.

**Infrastructure as code**: Can make changes to existing infrastructure as code under supervision.

## C3 - advanced

### Solution Design

**Applying Design Principles**: Takes ownership of significant aspects of the design within a large piece of work.

**Reusability**: Designs code for reuse with the support of more experienced team members.

**Aligning with business objectives**: Understands the desired business outcomes that influence solution designs.

**Technical Innovations**: Begins suggesting new technologies, developing an increasing appreciation of the impact they will have while requiring assistance from more experienced colleagues.

## Solution Implementation

**Solution delivery**: Delivers quality code that solves problems of low-moderate complexity without oversight, while beginning to mentor more junior team members around coding principles.

**Code quality**: Refactors code of low-moderate complexity.

**Coding standards**: Contributes towards code reviews of low-moderate complexity with support of other more experienced team members.

## Testing

**Foundation and Plan**: Knows how to effectively unit test only the discrete object, component or class using mocks as appropriate.

**Scope**: Can update component tests, potentially adding new component tests to an existing suite.

**Functional vs. Performance**: Can implement non functional tests appropriate to solutions built in their team - e.g. performance testing

**Approach**: Has an appreciation of tools available to support their testing, front-end or back-end as appropriate.

**Prioritisation**: Prioritise defects against issues/stories/features with guidance from more experienced team members.

## Security

**Awareness**: Able to define relevant security aspects and developments for the team they are in.

**Speaking up**: Escalates when they see perceived security issues.

**Compliance**: Shows some understanding of how we manage personal information, and why it's important.

**Infrastructure**: Can explain the concepts of security in relation to infrastructure elements of a solution.

**Independence**: Plays a part in identifying security issues and develops solutions that can be implemented by themselves or others.

## Monitoring, Alerting & Healing

**Monitoring and Alerting**: Understands existing performance metrics and with the support of more experienced team members take appropriate actions.

**Visualisation**: Build dashboards and defines key success metrics, suitable for both business and technical audiences, with the support of more experienced team members.

**Operational support**: Plays a part in identifying, supporting and debugging operational issues and develops solutions that can be implemented by themselves or others.

## DevOps

**CI/CD**: Can build a CI pipeline of low-moderate complexity without support.

**Containerisation**: When building a solution of low-moderate complexity should be capable of containerising it with support of more experienced team members.

**Infrastructure as code**: Can implement within a low to medium complexity solution infrastructure as code components.
